# Phase 5: Decision & HITL Processing
**Status**: VERIFIED & LOCKED
**Date**: August 2026

## Executive Summary
Phase 5 implements the **Decision & HITL (Human-in-the-Loop) Engine**. It acts as the ultimate business logic boundary. It ingests the strictly verified `EvidenceAssessment` from Phase 4, calculates the cumulative economics (Token Usage -> Cost), evaluates the Success Likelihood (P(Win)), calculates Net Expected Value (NEV), and strictly enforces the final chargeback decision (e.g., `CONTEST`, `ACCEPT`, `ESCALATE`).

Phase 5 explicitly relies on **deterministic math and configuration bounds** rather than raw LLM generation for final status outcomes. The LLM is used strictly to *explain* the deterministic outcome, not to invent it.

## 2. Decision Pipeline (LangGraph)

The execution path operates through highly restricted specialist nodes:
1. **Case Strength Node**: Evaluates the Phase 4 assessment for supporting/weak factors.
2. **Confidence Node**: Bounded confidence extraction.
3. **Risk Node**: Identifies critical conflicts or policy ambiguity.
4. **Explanation Node (LLM)**: Generates a human-readable justification. **Crucially, it employs a Grounding Validator**: the Python application intersects any `sources` generated by the LLM against `valid_evidence_ids`. Any hallucinated citations raise a strict validation error.

## 3. The Economics Engine & NEV

Phase 5 enforces real-world economics to dictate decisions. All constants scale via `app/config/settings.py`.

### A. Cumulative Token Accounting & Operational Cost
Tokens are accumulated from Phase 3 (Retrieval Planners), Phase 4 (Reasoning), and Phase 5 (Explanation).
- `Total Cost = (Input Tokens / 1000 * input_price) + (Output Tokens / 1000 * output_price)`

### B. Success Likelihood P(Win) [0.0, 1.0]
Calculated deterministically via `success_likelihood.py`:
- If `Critical Conflict` OR `Missing Critical Evidence` = `0.0`
- Base = `0.4`
- If Complete Evidence = `+0.2` (or `+0.05` if partial)
- Case Strength factor = `+ (Case Strength * 0.3)`
- Policy Alignment = `+0.1` (if no ambiguity)
- Final = `(Base) * Confidence`

### C. Expected Recovery & Net Expected Value (NEV)
- `Expected Recovery = P(Win) * Dispute Amount`
- `NEV = Expected Recovery - Cumulative Operational Cost`

## 4. Decision Rules Engine

Decisions are routed via `decision_engine.py` without LLM intervention:
- **Rule 1 (Fraud/Canceled & No Proof)**: If `dispute_type` == FRAUD and `confidence` < `DECISION_CONFIDENCE_THRESHOLD`, return `ESCALATE`.
- **Rule 2 (Critical Risk)**: If `critical_conflict` is True, return `ESCALATE`.
- **Rule 3 (Missing Evidence)**: If `missing_critical_evidence` is True, return `REQUEST_EVIDENCE`.
- **Rule 4 (Low Confidence)**: If `confidence` < `DECISION_CONFIDENCE_THRESHOLD` (Default 0.60), return `ESCALATE`.
- **Rule 5 (Negative NEV)**: If `NEV` < `DECISION_MIN_NEV` (Default 100.0 INR), return `ACCEPT`.
- **Rule 6 (Positive NEV)**: Otherwise, return `CONTEST`.

*(All recommendations are wrapped in `NEEDS_REVIEW` for the HITL queue).*

## 5. HITL (Human-in-the-Loop) State Transitions

All Phase 5 outputs land in the reviewer queue via `HumanReviewService`.

**API Contract (`POST /disputes/{id}/review`)**
Transitions are strictly guarded. A dispute must be in `NEEDS_REVIEW` to be processed.
| Current State | Action | New State |
|---|---|---|
| `NEEDS_REVIEW` | `APPROVE` | `FINAL_DECISION` |
| `NEEDS_REVIEW` | `EDIT` | `FINAL_DECISION` |
| `NEEDS_REVIEW` | `REQUEST_EVIDENCE`| `NEEDS_EVIDENCE` |
| `NEEDS_REVIEW` | `ESCALATE` | `ESCALATED` |

## 7. Instructions for Future Phases (Phase 6 / Integration / Frontend)
Future agents consuming this backend must adhere to the following rules:

1. **Do not re-calculate NEV**: Phase 5 provides the final calculated `economic_analysis`. Use it as-is.
2. **Rely on Final Artifacts**: The `DecisionArtifactModel` in the database contains the unalterable AI recommendation. 
3. **HITL Enforcements**: Frontends must restrict UI actions to match the `Action` enum in the Transition Table (e.g. `APPROVE`, `EDIT`, `REQUEST_EVIDENCE`, `ESCALATE`).
4. **Configuration First**: Any request to "tweak how eager the AI is to accept chargebacks" must be handled by changing `DECISION_CONFIDENCE_THRESHOLD` or `DECISION_MIN_NEV` in `settings.py`, NOT by changing code.
